# Модуль: Детекторы ПД (`detectors.py`)

Регэксп-детекторы персональных данных (ПД), разрешение пересечений, маскирование и токенизация.

## Назначение

Обнаруживает все типы ПД из ТЗ в тексте, определяет их границы (спаны), разрешает пересечения и заменяет значения на маску (`*`) или токены. Обеспечивает безопасное логирование.

## Поддерживаемые типы ПД

| Тип | Код | Регэксп |
|-----|-----|---------|
| ФИО | `FIO` | `_FIO_RE` |
| Дата рождения | `BIRTH_DATE` | `_DATE_NUM_RE`, `_DATE_NUM_REV_RE`, `_DATE_TEXT_RE`, `_DATE_TEXT_REV_RE`, `_DATE_TEXT_WORD_RE` |
| Место рождения | `PLACE_OF_BIRTH` | `_PLACE_BIRTH_VALUE_RE` |
| Серия и номер паспорта | `PASSPORT` | `_PASSPORT_LABELED_RE`, `_PASSPORT_PLAIN_RE` |
| Гражданство | `CITIZENSHIP` | inline-регэксп |
| Орган, выдавший паспорт | `ISSUER` | `_ISSUER_NAME_RE` |
| Код подразделения | `DEPARTMENT_CODE` | `_DEPT_CODE_RE` |
| Дата выдачи паспорта | `ISSUE_DATE` | даты + контекст `_ISSUE_DATE_CTX_RE` |
| Водительское удостоверение | `DRIVER_LICENSE` | `_DL_RE` |
| Адрес | `ADDRESS` | `_ADDR_CITY_RE`, `_ADDR_STREET_RE`, `_ADDR_HOUSE_RE`, `_ADDR_APT_RE`, `_ADDR_INDEX_RE` |
| Email | `EMAIL` | `_EMAIL_RE` |

## Механизм определения принадлежности к ПД

- **Публичные личности** (`_PUBLIC_PERSONS`): упоминания «Пушкин», «Толстой» и др. не маскируются как ФИО и место рождения.
- **Контекст документа** (`_FIO_DOC_CTX_RE`): ФИО маскируется только при наличии отчества или контекста («клиент», «заёмщик» и т.п.).
- **Контекстные регэкспы** (`_BIRTH_CTX_RE`, `_ISSUE_DATE_CTX_RE`, `_DL_CTX_RE`, `_DEPT_CODE_CTX_RE`): даты, паспорт, в/у и код подразделения маскируются только при наличии соответствующего контекста.

## Вариации написания (раздел 2.2 ТЗ)

- **Регистр** — все регэкспы используют `re.IGNORECASE` или `(?i:...)`.
- **Разное расположение даты** — `_DATE_NUM_RE` (дд.мм.гггг), `_DATE_NUM_REV_RE` (гггг.дд.мм).
- **Дата текстом** — `_DATE_TEXT_RE` (числовой день), `_DATE_TEXT_WORD_RE` (словесный день: «пятнадцатое марта 1990 года»).
- **Разделяющие слова** — `_PASSPORT_LABELED_RE` («серия хххх номер хххххх»), `_DL_RE` (до 20 нецифровых символов между серией и номером).

## Ключевые функции

### `mask_payload(text, allowed_types=None, mode="mask")`

Основная публичная функция.
- `allowed_types` — список типов ПД для маскирования (`None` = все);
- `mode="mask"` — замена на `*`;
- `mode="tokenize"` — замена на токены `[TYPE_N]`, возвращает карту `{токен: значение}` третьим элементом;
- возвращает `(замаскированный_текст, список_типов_ПД)`.

### `_detect(text)`

Собирает все спаны ПД. Логика:
1. ФИО (с проверкой публичных лиц и контекста);
2. место рождения (с исключением публичных лиц);
3. паспорт (labeled/plain, с учётом контекста в/у);
4. код подразделения, орган выдачи;
5. даты (числовые, текстовые, словесные);
6. водительское удостоверение;
7. адрес (город, улица, дом, квартира, индекс);
8. гражданство;
9. ИНН, карта, держатель карты;
10. телефон (с исключением контекста ИНН);
11. email;
12. CVV/PIN (только при найденной карте).

### `resolve_overlaps(spans)`

Выбирает непересекающиеся спаны: длиннее → выше приоритет → раньше.

### `mask_value(text)` / `mask_all(text)`

Полное скрытие: буквы/цифры → `*`, разделители сохраняются (`mask_value`) или все символы → `*` (`mask_all`).

> **Формат маскирования.** В исходном ТЗ указан **частичный** формат (например, `И. И. И.`, `45** ****56`). Организаторы позже решили маскировать **полностью** — все символы ПД скрываются (`*`). Наш сервис реализует **полное скрытие**.

### `redact_for_logging(text)`

Заменяет типовые ПД (паспорт, телефон, ИНН, карта, email) на `[REDACTED]` для безопасного логирования.

## Исправленные проблемы

- Гражданство (захват нескольких слов, двоеточие);
- Водительское удостоверение vs паспорт (конфликт приоритетов);
- ИНН vs телефон (конфликт приоритетов);
- Дата текстом (словесные дни);
- ФИО (захват служебного слова вместо отчества);
- Ложное срабатывание места рождения для публичных лиц.
