## Статус selftest

Команда: `python main.py --selftest`

Результат: **SELFTEST OK** (exit code 0).

Проверенные сценарии:
- пустой payload → пустой результат;
- первый запрос возвращает маску (ПД скрыты);
- повторный запрос с тем же оригиналом возвращает ту же маску;
- запрос с маской возвращает оригинал;
- отсутствие ПД → маска равна оригиналу;
- два одновременных запроса с одним `payload_id` дают одинаковый результат;
- запись не обновляется в спорном случае;
- фильтрация по `pii_types`;
- запрет демаскирования (`allow_unmask=false`);
- одинаковый payload с разными `payload_id` → одинаковая маска.

## Качество детекторов

Проверено 21 тестовым кейсом по всем типам ПД из ТЗ (ФИО, даты, паспорт, гражданство, орган выдачи, код подразделения, в/у, адрес, email, телефон, ИНН, карта, CVV, PIN, держатель карты, публичные личности, даты текстом и в разных форматах). Результат: **OK=21, FAIL=0**.

Исправленные проблемы:

- Водительское удостоверение vs паспорт (конфликт приоритетов);
- ИНН vs телефон (конфликт приоритетов);
- Дата текстом (словесные дни);
- ФИО (захват служебного слова вместо отчества);
- Ложное срабатывание места рождения для публичных лиц.

## Производительность

Нагрузочный тест (`python loadtest.py`, 100 keep-alive соединений, 4000 запросов):
- RPS: ~989 (цель ТЗ — 1000);
- p50: ~79 ms, p95: ~100 ms, p99: ~496 ms;
- max: ~1470 ms (единичный выброс при гонках на `payload_id`);
- ошибок нет.

Оптимизация: убрана глобальная `_metrics_lock` из горячего пути обработки запросов (RPS вырос с 930 до 989).

## Контракт POST /process

- `POST /process` с `{payload, payload_id}` → `{result}`;
- направление (маскирование/демаскирование) определяется по `payload_id`;
- идемпотентность к ретраям (блокировки на `payload_id`);
- `429` при перегрузке с `Retry-After`;
- `403` для отключённых/неизвестных систем;
- `GET /metrics` — Prometheus-формат (latency, rps, tps, счётчики типов ПД, 429).
