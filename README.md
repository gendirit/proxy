# PII Masking Service

Сервис маскирования и демаскирования персональных данных (ПД) с идемпотентным контрактом `POST /process`.

## Архитектура

- FastAPI-монолит с одним эндпоинтом `POST /process`.
- `detectors.py` — детекторы ПД (регэкспы, спаны, разрешение пересечений) и маскирование.
- In-memory `StateStore` с TTL/LRU хранит пары «оригинал ↔ маска» по `payload_id`.
- Блокировки на `payload_id` обеспечивают идемпотентность и защиту от гонок.
- `config.json` задаёт системы, типы ПД и флаг демаскирования.

## Быстрый старт

```bash
pip install -r requirements.txt
uvicorn main:app --host 0.0.0.0 --port 8000 --workers 1
python main.py --selftest
```

## Контракт POST /process

Запрос:

```json
{"payload": "Иванов Иван Иванович, паспорт 4509 123456", "payload_id": "req-1"}
```

Ответ:

```json
{"result": "****** **** **********, паспорт **** ******"}
```

Повторный запрос с тем же оригиналом возвращает ту же маску; запрос с маской возвращает оригинал. Коды: `200` — успех, `403` — система не найдена/отключена, `429` — перегрузка.

## Настройка систем и типов ПД

`config.json` содержит `default_system` и список `systems`. Заголовок `X-System-Id` выбирает систему по имени. Если система не найдена или `enabled=false`, сервис возвращает `403`. Поле `pii_types` ограничивает маскируемые типы ПД (значение `["ALL"]` — все типы). Флаг `allow_unmask=false` запрещает демаскирование и возвращает маску вместо оригинала. Запросы без заголовка всегда используют `default_system`.

## Безопасность логов

Персональные данные не попадают в логи: `RedactFilter` заменяет типовые ПД на `[REDACTED]`, а служебные записи логируются как JSON без исходного и маскированного текста.

## Нагрузочное тестирование

Запустите скрипт `loadtest.py` для проверки производительности:
