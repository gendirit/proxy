# Инструкция для жюри по проверке решения

Данный документ помогает проверить решение «Модуль безопасности персональных данных».

> **Формат маскирования.** В исходном ТЗ указан **частичный** формат (например, `И. И. И.`, `45** ****56`). Организаторы позже решили маскировать **полностью** — все символы ПД скрываются (`*`). Наш сервис реализует **полное скрытие**.

## URL сервиса

- **Эндпоинт:** `http://81.177.167.12:8001/process`
- **Healthcheck:** `http://81.177.167.12:8001/health`
- **Метрики:** `http://81.177.167.12:8001/metrics`

## 1. Проверка маскирования и демаскирования

Отправьте запрос на маскирование (первый запрос с новым `payload_id`):

```bash
curl -X POST http://81.177.167.12:8001/process \
  -H "Content-Type: application/json" \
  -d '{"payload":"Клиент Иванов Иван Иванович, паспорт 4509 123456","payload_id":"check-1"}'
```

Ожидаемый ответ: `{"result": "<замаскированная строка>"}` — ПД скрыты (`*`).

Затем отправьте запрос на демаскирование (второй запрос с тем же `payload_id`, payload = маска):

```bash
curl -X POST http://81.177.167.12:8001/process \
  -H "Content-Type: application/json" \
  -d '{"payload":"<маска из первого ответа>","payload_id":"check-1"}'
```

Ожидаемый ответ: `{"result": "Клиент Иванов Иван Иванович, паспорт 4509 123456"}` — исходная строка.

## 2. Проверка типов ПД

Сервис маскирует 17 типов ПД: ФИО, даты, паспорт, гражданство, орган выдачи, код подразделения, в/у, адрес, email, телефон, ИНН, карта, CVV, PIN, имя держателя.

Примеры для проверки:
- `"Паспорт 4509 123456"` → паспорт скрыт.
- `"Телефон: +7 999 123-45-67"` → телефон скрыт.
- `"ИНН 7707083893"` → ИНН скрыт.
- `"Карта 4509 1234 5678 9012, CVV 123, PIN 1234"` → карта/CVV/PIN скрыты.

## 3. Проверка негативных кейсов (не ПД)

- `"Александр Пушкин родился в Москве"` → не маскируется (публичная личность).
- `"Адрес отделения Банка: г. Москва, ул. Тверская, д. 1"` → не маскируется (адрес отделения Банка).

## 4. Проверка гибкой настройки

Настройка систем и типов ПД — в `config.json`:
- `systems` — список систем-потребителей.
- `pii_types` — типы ПД для маскирования.
- `allow_unmask` — разрешение демаскирования.
- `mask_mode` — режим маскирования (mask/tokenize).
- `mask_combinations` — контекстное маскирование.

Запрос с заголовком `X-System-Id` выбирает систему. Для отключённой системы возвращается `403`.

## 5. Метрики и логи

- `GET /metrics` — Prometheus-метрики (latency, rps, tps, типы ПД, 429).
- `GET /health` — healthcheck (200 при доступной БД).
- Логи — JSON, без исходных ПД (RedactFilter).

## 6. Производительность

- RPS ~2800 (цель ТЗ — 1000, повышенный уровень — 2000).
- Latency: p50 ~3.5ms, p95 ~19ms, p99 ~62ms.
- Обработка крупных текстов до 100 000 токенов.
