# Ограничения решения и план развития

> **Формат маскирования.** В исходном ТЗ указан **частичный** формат (например, `И. И. И.`, `45** ****56`). Организаторы позже решили маскировать **полностью** — все символы ПД скрываются (`*`). Наш сервис реализует **полное скрытие**.

## Ограничения решения

### Архитектурные
- **SQLite-хранилище:** не масштабируется на много писателей. При 8+ воркерах конкуренция за запись растёт (p99 увеличивается). Оптимально 3 воркера.
- **3 воркера по умолчанию:** зафиксировано для стабильности. На машинах с 8+ ядрами не использует все ядра (но это и не нужно, т.к. SQLite ограничивает).
- **Регэксп-детекторы:** CPU-интенсивные. Для очень больших текстов (100 000+ токенов) может потребоваться больше времени.

### Функциональные
- **Полное маскирование:** все символы ПД скрываются (`*`). Не поддерживает частичное маскирование (как в исходном ТЗ).
- **Синтетические данные:** не реализованы (токенизация покрывает критерий 7).
- **Двухкомпонентное ФИО:** может не маскироваться без отчества (требует контекста документа).

### Инфраструктурные
- **HTTP без HTTPS:** сервис доступен по HTTP (по ТЗ допустимо, проверка с `ssl_verify=false`).
- **IP-адрес вместо домена:** сервис доступен по IP (`http://81.177.167.12:8001`). Если AlfaSonar требует домен — нужна привязка домена.

## План развития после хакатона

### Краткосрочные улучшения
1. **Переход на Redis** — устранит конкуренцию за запись, позволит масштабировать на 8+ воркеров.
2. **Привязка домена** — если AlfaSonar требует домен (A-запись + reverse-proxy).
3. **HTTPS** — настроить TLS (Let's Encrypt или самоподписанный сертификат).

### Среднесрочные улучшения
4. **Синтетические данные** — замена ПД на сгенерированные значения (альтернатива токенизации).
5. **Двухкомпонентное ФИО** — добавить регэксп для 2-словных ФИО с контекстом.
6. **Оптимизация детекторов** — вынос в отдельный сервис или использование C-расширений.

### Долгосрочные улучшения
7. **Масштабирование** — горизонтальное масштабирование (несколько инстансов, балансировщик).
8. **ML-детекторы** — дополнение регэкспов ML-моделями для повышения точности.
9. **Мониторинг** — интеграция с системой мониторинга (Prometheus + Grafana).
