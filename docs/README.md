# Документация проекта «Модуль безопасности персональных данных»

Высоконагруженный прокси для LLM: идентификация, маскирование и демаскирование персональных данных (ПД) в цепочке «система-потребитель → LLM».

> **Формат маскирования.** В исходном ТЗ указан **частичный** формат маскирования (например, `И. И. И.`, `45** ****56`). Однако позже организаторы приняли решение маскировать **полностью** — все символы ПД скрываются (`*`). Наш сервис реализует **полное скрытие** персональных данных.

## Быстрый старт

```bash
pip install -r requirements.txt
python main.py --selftest        # проверка корректности
python main.py                   # запуск сервера на :8000 (4 воркера)
python loadtest.py               # нагрузочный тест (6 простых кейсов)
python bench.py                  # бенчмарк на разнообразном датасете (24 кейса)
bash pack.sh                     # сборка solution.zip
```

Переменные окружения:
- `DB_PATH` — путь к SQLite-файлу (по умолчанию `state.db`);
- `WORKERS` — число воркеров uvicorn (по умолчанию `cpu_count()-1`, автоопределение по числу ядер CPU).

## Контракт POST /process

```json
POST /process
{"payload": "<строка>", "payload_id": "<идентификатор>"}
→ 200 {"result": "<строка>"}
```

- Направление (маскирование/демаскирование) определяется по `payload_id`.
- Первый запрос с новым `payload_id` — маскирование; второй с тем же — демаскирование.
- Коды: `200` — успех, `403` — система отключена/не найдена, `429` — перегрузка, `422` — ошибка валидации.
